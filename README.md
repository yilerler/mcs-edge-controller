# V5 MCS 邊緣防禦架構 (Mixed-Criticality System Edge Architecture)
> **💡 Origin Story (緣起):** 本架構提煉自團隊協作專案「施工現場作業安全管理系統」。在經歷了複雜的多節點整合後，我將底層硬體與上層邏輯徹底抽離，獨立重構出這套具備「基礎設施無關性」的通用邊緣閘道器框架。

## 1. 執行摘要 (Executive Summary)

在多數的工業物聯網（IoT）與邊緣運算開發中，系統極易陷入「大爆炸式整合」的高耦合泥沼。以本架構的緣起專案（施工現場安全系統）為例，當我們試圖將門禁管制、空氣品質（MQ-3/135）與實體防禦（HC-SR04 超音波、心率異常中斷）等多個團隊分散開發的子系統揉合至單一閘道器時，我們面臨了巨大的「時間阻抗不匹配」：網路的微小延遲容易拖垮底層硬體的反射神經，而上層商業邏輯的改動，往往會牽動實體保命機制的崩潰。

為了解決 IT（資訊技術）與 OT（營運技術）在邊緣節點交鋒時的權責模糊與腦裂危機，**V5 MCS 架構**應運而生。這並非一個受限於特定場域（如工地）的應用程式，而是一套專為混合關鍵場域設計的**通用邊緣防禦基礎設施**。

本架構摒棄了將邊緣設備視為「毫無語意防禦的通訊翻譯機」之傳統作法，轉而確立了**「契約黑箱 (Contractual Black Box)」**的設計哲學。作為個人的核心架構實踐，V5 導入了以下機制：
* **24 Bytes 數位合約 (ICD)：** 實作強型別的記憶體邊界與語意漏斗。
* **ROS 2 狀態機 (FSM) 沙盒：** 達成防禦邏輯與硬體 I/O 的絕對解耦（依賴反轉）。
* **Layer 0 中斷特權：** 確保實體求生邏輯永遠凌駕於雲端營運指令之上。

透過本架構，未來的開發者可在此框架下自由抽換感測硬體或升級雲端安全機制（如 Zero Trust），而底層的核心保命防禦將不受任何波及。
